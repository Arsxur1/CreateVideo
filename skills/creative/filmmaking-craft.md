# Filmmaking Craft for OpenMontage — Classical Film Discipline, Translated to AI-Generated Video

> Source: Blain Brown, *The Basics of Filmmaking: Screenwriting, Producing, Directing,
> Cinematography, Audio & Editing* (Routledge, 2020) — curated and translated for the
> AI-generation pipeline. Korean reading copy: `docs/filmmaking-craft.ko.md`.

## Overview

Classical film craft was built to solve one problem: **make a movie that survives the editing
room.** A film that can't be cut is "uncuttable, unwatchable, undistributable." The craft rules —
coverage, the 180° line, the 30° rule, continuity, room tone, the Murch editing hierarchy — exist
to guarantee *cuttability* and *spatial coherence*.

AI-generated video looks exempt: no set, no crew, no slate. It is not. Every multi-shot narrative
generated by this pipeline still has to **cut** and still has to stay **spatially consistent** across
regenerations. The failure modes are identical: not enough angles to cut between, flipped screen
direction, jump cuts between near-identical shots, dead silence at every cut, a master with no
coverage to hide a weak moment.

This skill is a **translation table**: every physical-shoot rule is re-expressed as a concrete
constraint on an OpenMontage artifact (`script`, `scene_plan`, `asset_manifest`, `edit_decisions`).
Read the slice for the stage you are directing.

## When to Use

- Any **multi-shot narrative or cinematic** brief.
- Pipelines: `cinematic`, `hybrid`, `animation` (narrative), `character-animation`.
- Any scene that needs **cuttability** — i.e., almost any scene with more than one shot.

Skip for single-shot kinetic explainers, data-viz pieces, or pure motion-graphics with no spatial
continuity obligation (those are governed by `storytelling.md` and the motion-graphics playbooks).

## §1 Narrative Structure & Dialogue  (→ `script`)

### Plot vs Story — causality, not chronology

- **Plot** = the sequence of events ("the queen died, then the king died").
- **Story** = events linked by causality ("the queen died, **and then** the king died **of grief**").

A script beat list that reads "and then … and then … and then" is a plot, not a story. OpenMontage
inherits the **but-therefore** rule from `storytelling.md`: connect beats with **but** or
**therefore**, never with **and then**. If you cannot, the beat has no causal force — cut it or
raise the stakes.

### 3-Act structure (dramatic, not explainer)

Map these onto `script.structure` markers. This is the **dramatic** arc — distinct from the
explainer hook/tension/concept arc in `storytelling.md`; do not collapse the two.

| Beat | Position | Function |
|---|---|---|
| Setup | Act 1 | World, protagonist, ordinary state |
| Plot Point 1 (Inciting Incident) | ~25–30% | Turns the story; gives the protagonist a problem |
| Midpoint | ~50% | New obstacle, raised stakes, reversal |
| Plot Point 2 | ~75% | Crisis that forces the climax |
| Resolution | Act 3 | Emotionally satisfying ending — earned, not convenient |

### Conflict

Every scene needs conflict or it is dead weight. Types:
- External: person/person, person/society, person/nature, person/machine.
- Internal: the protagonist's own psychology.

A scene with no conflict either establishes stakes (acceptable, brief) or should be cut.

### Subtext — avoid "on-the-nose"

Dialogue/narration that states the emotion directly ("I am so sad") is on-the-nose. State the
**visual cause**, not the feeling. This re-enforces `storytelling.md`'s **Anti-Subjective Rule** —
subjective phrasing doesn't constrain pixels. Write the observable, not the felt.

### Show, don't tell (exposition)

Background information is a necessary evil; minimize it. Map every exposition beat to a **visual**
in `scene_plan` rather than dumping it in narration. If the audience must be told something, attach
it to action, not to a static voiceover block.

### Translation table — screenwriting rule → `script` artifact

| Rule | AI-gen constraint |
|---|---|
| Plot vs story | Beats linked by causality (`but`/`therefore`), not chronology. Reject "and then" chains. |
| 3-act | `script.structure` carries Setup / PP1 / Midpoint / PP2 / Resolution markers with rough positions. |
| Conflict | Every scene tagged with conflict type (external-*/internal); conflictless scenes flagged for cut. |
| Subtext | Narration describes observable cause, never bare emotion (Anti-Subjective Rule). |
| Show-don't-tell | Exposition mapped to `scene_plan` visuals; narration carries no static info-dumps. |

## §2 Coverage & Continuity  (→ `scene_plan`)   ← CORE SECTION

> **Coverage = cuttability. It is the #1 way movies fail, and the #1 way AI-gen scenes fail.**

A scene "covered" only by a single generated shot cannot be re-cut. When that one shot has a weak
moment, there is nowhere to hide. The master-scene method exists precisely so the editor always has
alternatives. In AI-gen, "shooting coverage" means **declaring multiple angles per scene and
generating them**, not hoping one shot is enough.

### Master scene method + coverage set

For each narrative scene, `scene_plan` declares:

1. **Master** — wide, establishes geography and the screen-direction axis for the whole scene.
2. **Coverage** — ≥2 additional angles: over-the-shoulder (OTS), close-up (CU), or cutaway/reaction.
3. **Cutaway/insert** — ≥1 reaction or detail insert so the edit can break a flat master.

Generate the master first; every coverage shot **references the master's axis** (same screen
direction, same geography). This is the single most important continuity anchor.

### The Line (180° rule)

An imaginary axis runs between two subjects (or between subject and the thing they look at). Once
the master is shot from one side of that line, **every other shot of that scene stays on the same
side**. Cross the line and screen direction flips — the audience's spatial map breaks.

**How to cross it legitimately** (when you must): show the camera moving across, cut away to a
neutral/insert shot, or cut to a neutral-angle shot on the line itself. Never flip silently.

### 30° / 20% rule + two-lens-sizes rule

Two shots that cut together must differ enough that the cut doesn't read as a jump cut (a glitch).

- **30° rule** — adjacent shots differ by ≥30° horizontally or vertically.
- **20% rule** — same idea, framed as ≥20% frame-size change.
- **Two-lens-sizes rule** — the reliable cutability trick: change **lens size** between coverage
  shots (e.g., 25 mm master → 50 mm close-up). Two lens sizes apart = always cuttable; one size is
  not.

When in doubt, make the change **bigger**, not smaller.

### Continuity types

Across all shots of a scene (and across regenerations), lock:

- **Wardrobe / appearance** — character descriptors identical across shots.
- **Screen direction** — a character facing screen-left stays screen-left across cuts.
- **Props** — objects present/absent consistently.
- **Time** — time-of-day / lighting state consistent within a scene.

Regeneration is the AI equivalent of a continuity error: every re-roll can silently change hair,
clothing, handedness, or facing. Pin these descriptors in a per-scene **continuity lock** and carry
them into every prompt for that scene.

### Establishing shots

Each scene opens with **geographic orientation** — a wide that tells the audience where they are —
before tighter coverage. A scene that starts on a close-up with no sense of place feels unmoored.

### Translation table — the killer feature

| Physical-shoot rule | AI-gen constraint |
|---|---|
| "shoot coverage for every scene" | `scene_plan` declares **≥3 angles per narrative scene**: master + 2 coverage (OTS / CU / cutaway) so edit has cutability. |
| "master scene method" | Generate a **master first** (establishes geography + axis); every coverage shot references that axis. |
| "always shoot a cutaway" | Every scene includes **≥1 cutaway/reaction** insert to break a flat master. |
| The Line / 180° | All shots of one scene share a **screen-direction axis**; flag any axis flip as a continuity violation. Fix screen direction in the gen prompt. |
| 30° / 20% rule | Adjacent generated shots differ **≥30° or by ≥20% frame size**, else jump-cut risk → regenerate or reframe. |
| Two-lens-sizes | Cut coverage by **changing lens size** (e.g., 25 mm → 50 mm); two sizes apart = always cuttable. |
| Continuity (wardrobe/dir/props/time) | Per-scene **continuity lock** (appearance, screen direction, time-of-day, props) carried into every prompt; regeneration preserves locked descriptors. |
| Establishing shot | Each scene opens with **geographic orientation** (wide) before closer coverage. |

## §3 Editing Decisions  (→ `edit`)

### Walter Murch's Rule of Six — in priority order

When two candidate cuts compete, settle by priority. The list is **ordered** — emotion dominates.

1. **Emotion** — does the cut serve the feeling of this moment?
2. **Story** — does it advance meaning?
3. **Rhythm** — does it land on the beat, just before the viewer expects?
4. **Eye-trace** — where is the viewer's eye, and where does the cut send it?
5. **2D place on screen** — does it respect the 180° axis?
6. **3D space** — does it preserve physical/spatial relationships?

A cut that is rhythmically perfect but emotionally wrong loses. A cut that is emotionally right
but breaks the line can still win — if the lower priorities are the only casualties.

### Six-pass editorial process → `edit_decisions`

| Pass | Film term | OpenMontage mapping |
|---|---|---|
| 1 | Logging | Review every generated clip; tag usable takes, discard failed regenerations. |
| 2 | First assembly | Order clips to follow the `script` structure (the sketch). |
| 3 | Rough cut | Check scene order + continuity; fix line violations, jump cuts. |
| 4 | First cut | Structure locked with the director/producer (human gate). |
| 5 | Fine cut | Tighten rhythm; apply Murch priority to every contested cut. |
| 6 | Final cut | Sound design, music, titles added; the deliverable. |

### J-cut / L-cut

- **J-cut** — audio of the next shot begins **before** its video (audio leads).
- **L-cut** — audio of the current shot continues **after** cutting to the next video (audio trails).

Both extend the basics in `skills/creative/video-editing.md`. Use them to smooth dialogue hand-offs
and to let a sound bridge carry the viewer across a cut.

### Hidden cuts, match cuts, cross-cutting, ellipsis

- **Hidden cut / match cut** — action or frame matches across the cut so it reads as continuous.
- **Cross-cutting** — alternate two scenes to build parallel tension.
- **Ellipsis** — compress time by cutting out the middle.
- **Establishing geography** — open a sequence wide so later tighter cuts have a spatial home.

### Decision framework

When two candidate cuts compete: walk Murch's list top-down; the first priority that distinguishes
them wins. Log the reasoning in `edit_decisions` for the contested cut so a re-edit doesn't relitigate it.

## §4 Audio Craft — Translated  (→ `assets`)

Physical audio rules were about microphones on a set. In AI-gen the "microphone" is the TTS engine
and the ambient generator, but the **intent** of each rule survives.

| Physical rule | AI-gen translation |
|---|---|
| Rule #1 "get the mic close" | TTS **is** the dialogue — no boom-distance problem. But ensure a **clean, isolated narration take**: voice on its own stem, no music/SFX bleed, so the mixer can duck around it (`sound-design.md`). |
| Rule #2 "always record" | **Always generate an ambient bed** for every location, even scenes that feel silent. Silence in film is never digital zero. |
| Room tone (≥15 s per location) | One **consistent ambient/room-tone track per location**, reused across every cut in that location. Without it, cuts pop. |
| ADR (expensive, never as good) | Get the TTS take right **the first time**. Regenerating the voice mid-edit is the AI equivalent of expensive ADR — lock provider + voice + settings before batch. |
| Scratch track | Generate **rough TTS first** to lock timing, then the final voice pass. Scratch narration lets `scene_plan`/`edit` time to real words before the voice is committed. |

The principle: **audio is half the film, and cuts live or die on the ambient bed underneath them.**
A scene with a great visual and a popping, dead-quiet cut feels amateur.

## §5 Anti-Pattern Checklist — "Top Ten Ways to Screw Up Your Movie"  (→ review / self-eval)

Brown's "Top Ten" is mostly a physical-set list. The subset that maps to AI-gen, each re-expressed
as a check:

| Screw-up | AI-gen check |
|---|---|
| "not enough coverage" | Does `scene_plan` declare **≥3 angles per narrative scene**? |
| "no cutaways" | Does each scene include **≥1 cutaway/reaction**? |
| "bad audio" | Is there a **consistent ambient bed per location** + an isolated narration stem? |
| "no establishing shot" | Does each scene open with **geographic orientation**? |
| "we'll fix it in post" | Is anything being **deferred to `edit`** that should be fixed at `scene_plan`/`assets`? (Coverage and continuity cannot be fixed in edit — they must exist upstream.) |
| "weak script" | Does the script have **conflict + causality**, not just a sequence of events? |

**Pruned (physical-only, N/A to AI gen):** bad focus, unintended camera shake, bad exposure, bad
camera level, room tone "not recorded on set." Exposure/focus map to image-gen quality gates
handled elsewhere; shake and level are non-issues for generated frames.

The meta-anti-pattern: **"we'll fix it in post."** In an AI pipeline this reads as "the edit stage
will hide that the scene has no coverage." It will not. Cuttability is created at `scene_plan`,
not rescued at `edit`.

## Self-Evaluation Rubric

Score each row 1–5 (5 = fully satisfied). Any 1–2 is a critical finding — fix before checkpointing.

| Criterion | 1–5 | What 5 looks like |
|---|---|---|
| Coverage | | Every narrative scene has master + ≥2 coverage + ≥1 cutaway, all generated. |
| Axis consistency (180°) | | No screen-direction flips within a scene; axis explicitly carried from master. |
| Cuttability (30°/lens) | | Adjacent shots differ ≥30° or two lens sizes; no jump-cut-risk pairs. |
| Establishing shots | | Every scene opens with geographic orientation. |
| Continuity lock | | Appearance / screen direction / props / time pinned and preserved across regenerations. |
| Audio bed | | Consistent ambient per location; isolated narration stem; no popping cuts. |
| Script craft | | Causal beats (`but`/`therefore`), conflict in every scene, observable-not-subjective narration. |
| Anti-pattern pass | | §5 checklist clean; nothing deferred to edit that belongs upstream. |

## Common Pitfalls

- **One angle per scene.** The classic. Generates a single "nice" shot with nowhere to cut. Always declare coverage.
- **Silent screen-direction flips.** Regeneration flips a character's facing and nobody catches it. Carry the axis + continuity lock into every prompt.
- **Near-identical adjacent shots.** Two CUs from almost the same angle = jump cut. Enforce 30°/two-lens-sizes.
- **No ambient bed.** Every cut lands on digital silence. Generate and reuse room tone per location.
- **"Fix it in post."** Hoping the edit rescues missing coverage. It cannot — coverage is an upstream decision.
- **On-the-nose narration.** Stating feelings instead of showing their visual cause (violates Anti-Subjective Rule).
- **Treating AI-gen as exempt from continuity.** It is the opposite: regeneration is a *built-in* continuity hazard, so locks matter more, not less.
