## 3. 조사 결과 요약

### SOTA 영상모델 (WAN 2.2 기준)
- **WAN 2.2 14B가 여전히 최강** (Apache 2.0, LoRA 생태계 최대, photoreal 우위)
- 대안: LTX-2.3(속도强·라이선스 제한), HunyuanVideo 1.5(motion强)
- 8GB에선 WAN 2.2 14B → GGUF Q8로 겨우(느림). 속도 병목시 LTX-2.3 fallback
- **경고:** head-to-head 정량 벤치마크 부재, 3개월마다 재평가 권장

### 프로바이더 분석 (8GB 관점)
- **ComfyUI** — REST 클라이언트, 프롬프트 자동 주입(node "4"). 번들 FLUX 2 NVFP4 ~8GB라 Blackwell에 불안정
- **Higgsfield** — OpenMontage에선 영상 전용(`higgsfield_video`), 이미지 도구 없음. 클라우드(8GB 무관)
- **MCP** — 레지스트리와 분리(image_selector가 MCP 모름). provided 경로로만 우회 가능
- **Pexels** — 무료 실사 스톡, 1키=이미지+영상. 실사 자연 씬에 최적, 추천
- **제공 에셋(provided)** — 어떤 키도 없이, 바깥 생성 이미지 드롭으로 영상 완성 가능

## 5. 핵심 인사이트 (데모 콘텐츠)

research가 찾은 단일 핵심: **"인생의 아름다움"은 기다리는 상태가 아니라 훈련 가능한 주의 행위.**
- Hunter 2019: 자연 20~30분 → 코르티솔 감소
- Piff/Keltner 2015: 1~2분 awe → "작은 자교" → 이타성
- Bryant: savoring = 훈련 가능 기술
- 한국어 **푸르름** = 생명·희망·청춘·재생 동시 의미 (윤동주 서시가 시적 뿌리)
- **carpe diem 오역** — "붽잡다"가 아니라 "꽃을 따다"(carpere)

## 6. 정직 기록 — 벗어난 부분

Rule Zero(매 단계 전 디렉터 스킬 읽기) 미완전 준수:
1. `proposal-director.md` 미읽음 — research angles + 스키마로 직접 조립
2. `reviewer` 스키 경량 적용 — 스키마 검증 + 커버리지 점검으로 대체
3. research를 서브에이전트에 위임 — 프로토콜은 이식, 직접 실행 아님
4. 모델 조사 워크플로 4/5 에이전트 스키마 실패 — 종합 1개로 단일조사 신뢰도

데모 목적엔 영향 없으나, 실제 제작에선 스킬 충실히 읽어야 품질 보장.

## 7. 현재 상태 + 열린 스레드

1. 이미지 4장 — 바깥에서 만들어 `assets/images/` 드롭(sc01 메뚜기 · sc02a 석녘바다 · sc02b 비행기창 · sc10 야생화) → provided로 연결. **어떤 키도 불필요.**

3. 그러면 assets→edit→compose → `renders/final.mp4`

**또는** provider 키 하나(PEXELS_API_KEY 무료 추천 / FAL_KEY) → assets 자동 잠금해제.
