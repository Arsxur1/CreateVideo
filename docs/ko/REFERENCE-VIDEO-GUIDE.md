# 레퍼런스 영상 분석 — 쉽게 이해하기

> AGENT_GUIDE의 "Reference Video Entry Point" 부분을 초보자용으로 풀어쓴 문서.
> 어렵게 느껴졌다면 이 문서부터 읽으세요.

---

## 한 줄 요약

**영상 링크 하나를 붙여넣으면, 에이전트가 그 영상을 분석해서 "비슷한 느낌의 새 영상" 기획안을 만들어 줍니다.**

```
당신: "[YouTube 링크] 이런 느낌으로 만들어 줘"
         ↓
에이전트: 영상을 다운로드 → 대사·장면·화면·스타일 분석
         ↓
에이전트: "이 영상은 이래서 좋습니다. 이렇게 바꾸면 당신만의 버전이 됩니다"
         ↓
기획안 2~3개 + 비용 견적 + 샘플 제공
```

---

## 왜 쓰나요?

빈 프롬프트에서 시작하면 "완벽한 프롬프트"를 혼자 지어내야 해서 어렵습니다.
**좋아하는 영상을 주면 출발점이 생깁니다.** 페이스, 분위기, 구조를 그대로 배우고,
주제와 각도만 바꿔서 당신 버전을 만듭니다. 훨씬 빠르고 정확합니다.

---

## ⚠️ 가장 중요한 구분 하나

에이전트는 두 요청을 완전 다르게 처리합니다. 헷갈리면 안 됩니다:

| 당신의 말 | 의미 | 에이전트의 행동 |
|---|---|---|
| **"이 영상 *편집해 줘*"**, "*잘라 줘*" | 내 영상을 손봐 달라 | → **편집 파이프라인** (footage-led) |
| **"이런 *느낌으로* 만들어 줘"**, "*비슷한 거*" | 이 스타일의 새 영상을 원한다 | → **레퍼런스 분석** (이 문서의 기능) |

- "편집" = 이미 찍은 영상을 자르고 붙이는 것.
- "느낌으로" = 그 영상에서 배울 점을 뽑아 **새 영상**을 기획하는 것.

---

## 에이전트가 영상을 분석할 때 하는 일 (5단계)

에이전트가 영상을 "본다"는 건, 사실 여러 도구가 영상을 분해해서 에이전트에게
자료를 주는 것입니다. 순서:

```
1. 다운로드      video_downloader   영상 파일을 로컬로 가져옵니다
2. 대사 뽑기     transcript_fetcher 말소리를 텍스트로 바꿉니다 (자막·대본)
3. 장면 쪼개기   scene_detect       화면이 바뀌는 지점을 찾아 장면 단위로 나눕니다
4. 핵심 화면     frame_sampler      각 장면의 대표 프레임(사진)을 뽑습니다
5. 이해          에이전트(시각 모델) 뽑아진 프레임을 직접 보고 스타일·구조·흐름을 해석합니다
```

**핵심:** 도구들은 영상을 "데이터"로 쪼개주고, **진짜 이해는 에이전트가 합니다.**
에이전트는 뽑힌 프레임 사진들을 눈으로 보며 색감·구도·텍스트·전환 패턴까지 읽어냅니다.

---

## 5가지 관점으로 쪼개어 본다

에이전트는 영상을 **다섯 가지 관점**으로 정리합니다 (CMU/Harvard 연구 기반).
이 구조가 있어야 기획안이 정확해집니다.

| 관점 | 보는 것 | 예시 |
|---|---|---|
| **피사체 (Subject)** | 무엇이 나오는지, 몇 개, 어떤 특징 | "젊은 여성 1명, 흰 드레스" |
| **피사체 움직임** | 어떤 동작을 하는지 | "걷는다 → 멈춘다 → 하늘을 본다" |
| **장면 (Scene)** | 배경·시간대·글자/그래픽·POV | "초원, 황혼, 자막 없음, 드론 시점" |
| **구도 (Framing)** | 피사체 위치, 화면 크기, 깊이 | "전신 샷, 중앙, 앞/뒤경경 있음" |
| **카메라 (Camera)** | 렌즈, 각도, 움직임, 초점 | "아이레벨, 핸드헬드, 슬로우모션" |

해당하지 않으면 **"N/A"** 라고 명시합니다. 빠뜨리면 기획이 흐려집니다.

---

## 특히 중요한 판단: "이 영상, 사진인가 영상인가?"

에이전트는 각 장면이 어떤 종류인지 분류합니다:

- **`motion_clip`** → 진짜 움직이는 영상 생성 (Kling, Veo 등)이 쓰였다
- **`animated_still`** → 사진에 줌/팬(Ken Burns)을 줘서 움직인 것이다
- **`static_image`** → 정지 이미지

이 판단을 **틀리면** 잘못된 파이프라인을 제안합니다. 에이전트는 절대 추측하지 않고
이 필드를 읽습니다. 예: 대부분 `motion_clip`이면 → "영상 생성 도구 필요"로 계획.

---

## 분석이 끝나면 뭐가 나오나요?

에이전트가 주는 것 (그냥 찍힌 데이터가 아니라 **대화형 해석**):

1. **영상 요약** — 내용·스타일·구조·왜 잘되는지 (2~3문장)
2. **5관점 분해** — 위 표대로 정리된 자료
3. **"잘 되는 이유"** — 훅 기법, 페이스, 전환 스타일 등
4. **기획안 2~3개** — 각각 다른 각도 (아래 표 참고)
5. **비용 견적** — 각 기획안별, 도구별로 쪼개서
6. **샘플** — 10~15초짜리 미리보기 (정식 제작 전)

### 차별화 패턴 (그냥 복사가 아닌 이유)

| 패턴 | 예 |
|---|---|
| 같은 구조, 다른 주제 | 원본 "블랙홀" → ours "중성자별" |
| 같은 주제, 다른 각도 | 원본 "Kubernetes 설명" → ours "보안 엔지니어 시점" |
| 같은 톤, 다른 비주얼 | 원본 실사 → ours 모션그래픽 |
| 다른 플랫폼 | 원본 10분 유튜브 → ours 60초 쇼츠 |
| 반대 주장 | 원본 "AI가 일자리 뺏는다" → ours "당신 일자리는 안 뺏긴다" |

**에이전트는 절대 똑같이 베끼지 않습니다.** 원본은 영감이지 복사본이 아닙니다.

---

## 어떻게 쓰나요? (프롬프트 예시)

설치 후 AI 어시스턴트에 그대로 붙여넣으세요:

```
"제가 좋아하는 YouTube Short입니다. [링크]
 이런 느낌으로, 주제는 '인생은 아름답다'로 만들어 주세요."
```

```
"이 Reel 분석해서, 내 제품 런칭에 쓸 오리지널 변형 3개만 제안해 주세요. [링크]"
```

```
"이 영상의 페이스와 훅이 마음에 들어요. 그 에너지는 살리고,
 블랙홀을 주제로 한 45초 설명 영상으로 바꿔 주세요. [링크]"
```

YouTube · Shorts · Reels · TikTok · 로컬 파일 모두 가능합니다.

---

## 내 컴퓨터에서 분석이 되나요?

**분석 자체는 GPU가 없어도 됩니다.** 분석 단계가 쓰는 도구들:

- 영상 다운로드 (yt-dlp)
- 대사 추출 (Whisper, 로컬)
- 장면 감지 (PySceneDetect)
- 프레임 추출 (FFmpeg)

이것들은 **CPU로 돕니다.** 영상을 "이해"하는 건 가능합니다.

다만, **분석 뒤 "새 영상을 만드는" 단계**는 생성 도구(이미지·영상 생성)가 필요하고,
여기서 GPU/API 키가 들어갑니다. 즉:

- ✅ **영상 분석** → 8GB 노트북도 가능
- ⚠️ **새 영상 생성** → GPU 또는 API 키 필요 (분석 결과만 받고 생성은 건너뛸 수도 있음)

## 자주 묻는 질문

**Q. 링크가 안 열리면?**
A. 로컬 영상 파일을 직접 줄 수도 있습니다. 다운로드 실패 시 에이전트가 대안을 제시합니다.

**Q. 자막이 없는 영상은?**
A. 영상을 다운로드해서 Whisper로 직접 대사를 뽑습니다.

**Q. 여러 영상을 한꺼번에?**
A. 가능합니다. 각각 따로 분석하고 비교 요약을 줍니다 ("A는 이게 좋고, B는 저게 좋다").

**Q. 분석이 다 실패하면?**
A. 에이전트가 당신에게 영상을 말로 설명해 달라고 부탁합니다. 일반 기획 흐름으로 넘어갑니다.
