# 한국어 로컬라이제이션 로드맵 — 설계 스펙

- 작성일: 2026-07-19
- 상태: 승인 대기
- 범위: OpenMontage 영어 문서 전체의 한국어 이중언어 번역 + 원본 변경 추적 인프라

## 1. 목표

OpenMontage의 사용자·기여자 대면 영어 문서 9개(총 약 3,600줄)를 한국어 이중언어 문서로 번역하고, 영어 원본 변경 시 번역의 stale 여부를 추적하는 최소 인프라를 갖춘다.

완료 기준:

- 9개 원본 각각에 대응하는 `docs/ko/` 번역 파일 존재
- 모든 번역 파일이 품질 게이트(§6) 통과
- `scripts/check-ko-drift.py` 실행 시 전 파일 `OK` 출력
- 기존 완료 파일 3개(`README_ko.md`, `docs/ko/USAGE.md`, `docs/ko/KIMI-SETUP.md`)에도 원본 해시 헤더 백필 완료

## 2. 배경과 선례

- `README_zh-CN.md`는 중국어 단독 파일 선례. 그러나 이번 한국어 작업은 `docs/ko/`에서 확립한 **이중언어 병기** 형식을 채택한다(사용자 결정, 2026-07-19).
- 이중언어 형식: 각 섹션에 영어 원문이 먼저 나오고, `**[한국어]**` 마커 줄 아래에 한국어 번역이 이어진다. 섹션 헤딩은 `## English Title (한국어 제목)` 형태.
- 이미 완료된 작업: `README_ko.md`(병합 완료, 1,391줄), `docs/ko/USAGE.md`, `docs/ko/KIMI-SETUP.md`. `_draft_readme_part1/2.md`는 병합이 끝난 중간 산출물.

## 4. 번역 형식 규칙

기존 `docs/ko/` 작업물과 동일한 규칙을 모든 신규 파일에 적용한다.

1. 파일 상단: 이중언어 안내 블록인용(`> 이 문서는 이중 언어 문서입니다. 각 섹션에서 영어 원문이 먼저 나오고, **[한국어]** 표시 아래에 한국어 번역이 이어집니다.`).
2. 그 아래 원본 추적 헤더(§5): `> 원본: <path> @ <full-commit-hash>`.
3. 섹션마다 영어 원문 → `**[한국어]**` 마커 줄 → 한국어 번역.
4. 헤딩은 `## English Title (한국어 제목)` 병기.
5. 코드 블록, 셸 명령, 파일 경로, URL, 환경변수명, 모델 ID는 **절대 번역하지 않고 verbatim** 유지. 코드 블록 내 주석은 영어 유지 후 한국어 주석을 미러링할 수 있음(기존 `.env` 블록 관례).
6. 표는 구조 유지, `[한국어]` 블록에서 헤더 셀 포함 전체를 한국어로 재표기.
7. 뉴트럴하고 자연스러운 한국어(합니다체). 기술 용어는 관용 차용어 허용(파이프라인, 체크포인트, 렌더링, 에이전트, 프로바이더). 해요체/합니다체 혼용 금지 — 합니다체로 통일(KIMI-SETUP 리뷰에서 확립).
8. 어휘 일관성: provider → 프로바이더, pipeline → 파이프라인, render → 렌더링, checkpoint → 체크포인트, decision log → 의사결정 기록.

## 5. 동기화 인프라

### 5.1 원본 추적 헤더

모든 번역 파일(신규 9개 + 기존 3개 백필)에 다음 형식의 헤더를 둔다:

```
> 원본: docs/PROVIDERS.md @ 3f9a1c...<전체 해시>
```

- 해시는 번역 시점의 원본 파일이 속한 최신 커밋(`git log -1 --format=%H -- <path>`).
- `README_ko.md`는 원본이 `README.md`, `docs/ko/USAGE.md`와 `docs/ko/KIMI-SETUP.md`는 한국어 오리지널 문서이므로 해시 대신 `> 원본: (한국어 오리지널 — 대응 원본 없음)`으로 표기한다. 단, `KIMI-SETUP.md`와 `USAGE.md`는 내용이 영어 원본 없이 작성된 문서이므로 drift 체크 대상에서 제외한다.

### 5.2 drift 체크 스크립트

`scripts/check-ko-drift.py`:

- `docs/ko/*.md`와 루트 `README_ko.md`를 스캔해 `> 원본: <path> @ <hash>` 헤더를 파싱.
- 각 항목에 대해 `git log -1 --format=%H -- <path>`로 현재 원본 해시를 조회.
- 해시가 다륩면 `STALE: <번역 파일> (원본 <old> → <new>)`, 같으면 `OK: <번역 파일>` 출력.
- `(한국어 오리지널)` 표기 파일은 `SKIP` 처리.
- 종료 코드: STALE 1개 이상이면 1, 아니면 0 (CI/훅 연동 가능).
- 외부 의존성 없음(stdlib만, `subprocess`로 git 호출).

### 5.3 AGENT_GUIDE.md 특수 규칙

- 번역본 헤더에 경고를 추가한다: `> ⚠️ 참조용 번역입니다. 에이전트 동작 계약의 정본은 영어 원본 [AGENT_GUIDE.md](../../AGENT_GUIDE.md)입니다.`
- `CLAUDE.md` 등 루트 포인터 파일은 계속 영어 원본을 가리키게 유지한다(변경 금지). 번역본을 에이전트가 읽는 경로로 연결하지 않는다.

## 6. 품질 게이트 (파일당 필수)

번역 에이전트 출력이 다음을 모두 통과해야 완료로 인정:

1. **커버리지**: 원본의 헤딩 목록(레벨 1~6, **코드펜스 내부 제외**)과 번역본의 헤딩 목록이 순서·개수·영어 문구 일치(스크립트 비교).
2. **글리프 무결성**: 깨진 한글 패턴 grep 0건(`물묣`, `물료`, `난레이션`, `침침`, 한글 음절 내 난입한 라틴 대문자 토큰 등 — README 작업에서 실제 발생한 패턴 목록 사용).
3. **불변 영역**: 코드 블록(``` 펜스 난), URL, 파일 경로가 원본과 동일(스크립트 diff).
4. **마커 존재**: `**[한국어]**` 마커가 섹션 수만큼 존재.
5. **어체 통일**: `~세요` 종결 grep 0건(합니다체 강제).

## 7. 실행 계획

방식: **병렬 워크플로우**(README 작업에서 검증된 번역→리뷰→자동수정 팬아웃 패턴).

### 단계 0 — 인프라 (메인 세션, 에이전트 불필요)

1. `scripts/check-ko-drift.py` 작성.
2. 기존 3개 완료 파일에 원본 헤더 백필.
3. `_draft_readme_part1/2.md` 정리 여부 사용자 확인 후 삭제(병합 완료된 중간 산출물).
4. `docs/ko/USAGE.md` 상단 "Related guides"에 `README_ko.md` 링크 복원(이전에 죽은 링크라 제거됐으나 이제 실체 파일 존재).

### 단계 1 — 번역 팬아웃 (에이전트 9개, 병렬)

- 파일당 번역 에이전트 1개. 프롬프트에 §4 형식 규칙 + §5 헤더 규칙 + 품질 게이트 자가검증 요구사항 포함.
- `docs/PROVIDERS.md`와 `AGENT_GUIDE.md`는 단독 에이전트로 최우선 배정(최대 파일).
- 각 에이전트 최종 보고: 섹션 목록, 줄 수, 자가검증 결과.

### 단계 2 — 리뷰+수정 팬아웃 (에이전트 9개, 병렬)

- 파일당 리뷰 에이전트 1개: §6 품질 게이트 전 항목 검사 + 발견 즉시 인플레이스 수정 + 수정 내역 보고.
- 수정 후 재검증까지 수행(게이트 무통과 파일 0개 확인).

### 단계 3 — 최종 검증 (메인 세션)

1. 전 파일 게이트 스크립트 일괄 실행.
2. `scripts/check-ko-drift.py` 실행 — 전 파일 `OK`/`SKIP` 확인.
3. 결과 요약 보고.

### 커밋 전략

사용자 지시에 따라 커밋은 수행하지 않는다(2026-07-19). 커밋 시점과 단위는 사용자가 별도 지시.

## 8. 비범위 (YAGNI)

- CI/GitHub Actions 연동(drift 스크립트는 수동 실행으로 시작; 종료 코드 규약만 맞춰둠).
- `README.md`에 언어 링크 추가(현재 zh-CN도 링크 없음 — 업스트림 정책 확인 전 변경 금지).
- 주석·코드 낸 docstring 한국어화.
- 스타일 플레이북(`styles/*.yaml`), 파이프라인 매니페스트 등 기계 소비 YAML.
